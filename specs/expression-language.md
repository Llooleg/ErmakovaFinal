# Спецификация языка выражений

## 1. Представление

Формула хранится как типизированное дерево. Листьями являются переменные `x₁…xₘ` и свободные численные параметры. Внутренними узлами являются арифметические операции, функции одного аргумента и степень.

Минимальная абстрактная грамматика:

```text
Expr    := Variable
         | Constant
         | Unary(Function, Expr)
         | Binary(ArithmeticOperator, Expr, Expr)
         | Power(Expr, ExponentParameter)
```

Каждый параметр имеет имя, текущее значение, допустимый диапазон и признак возможности оптимизации. Строковое представление используется только для отображения; вычисление выполняется обходом дерева.

## 2. Независимые переменные

1. Переменные обозначаются `x₁…xₘ` и связываются с данными через конфигурацию `FeatureProvider`.
2. Переменная может быть временем, прошлым значением целевого ряда или другой причинно допустимой производной входного CSV.
3. Для наблюдения `t` разрешены только данные, доступные в момент формирования прогноза для `t`.
4. Если используются лаги, начальные наблюдения без полной истории исключаются из оценки либо обрабатываются явно заданным правилом. Неявная подстановка будущих значений запрещена.
5. Масштабирование переменных входит в сохраняемое определение формулы.

## 3. Каталог элементарных функций

Каталог должен обеспечивать представление следующих классов:

| Класс | Базовые узлы или каноническое представление |
|---|---|
| Константа и тождественная функция | `c`, `x` |
| Линейные и полиномиальные выражения | `a·x+b`, композиции `+`, `−`, `·`, степени |
| Степенная функция | `u^p` с параметризованным `p` |
| Корни | частные случаи степени с учётом области определения |
| Обратные степени | `u^(−p)` при допустимом `u` |
| Показательная функция | `exp(u)`, экспонента с другим основанием через `exp(u·ln a)` |
| Логарифмическая функция | `ln(u)`, логарифм по основанию `a` через смену основания |
| Прямые тригонометрические | `sin(u)`, `cos(u)`, `tan(u)`; остальные через тождества |
| Обратные тригонометрические | `arcsin(u)`, `arccos(u)`, `arctan(u)`; остальные через согласованные тождества |
| Гиперболические | `sinh(u)`, `cosh(u)`, `tanh(u)` или их экспоненциальные формы |
| Обратные гиперболические | `asinh(u)`, `acosh(u)`, `atanh(u)` или их логарифмические формы |

Производные функции могут иметь удобные именованные узлы, но каноническая форма не должна дублировать одно и то же выражение под разными названиями.

## 4. Параметризация

### 4.1 Коэффициенты

Линейные коэффициенты перед подвыражениями и свободный член являются отдельными параметрами. Если структура линейна по этим коэффициентам, они оцениваются методом наименьших квадратов.

### 4.2 Степени

Степень `p` является свободным параметром в заданных границах. Для произвольного вещественного `p` основание должно быть положительным. Целые и рациональные степени обрабатываются по отдельным математическим правилам, а не общим вещественным приближением.

### 4.3 Периоды

Периодические зависимости записываются в виде:

```text
sin(2π·(x+s)/T)
cos(2π·(x+s)/T)
```

где `T>0` — период в единицах переменной `x`, `s` — сдвиг. Такая запись не смешивает период с частотой и сохраняет физическую размерность.

### 4.4 Сдвиги

Сдвиг `s` является параметром аргумента функции, например `ln(x+s)` или `(x+s)^p`. Он не должен означать считывание прогноза из будущей точки `ŷ(t+δ)`.

## 5. Области определения и непрерывность

Кандидат принимается только при конечных вещественных значениях на всём рабочем диапазоне.

| Операция | Обязательное ограничение |
|---|---|
| `u/v` | `v≠0`; знаменатель не должен обращаться в ноль внутри рабочего диапазона |
| `ln(u)` | `u>0` |
| `u^p`, вещественный `p` | `u>0`, кроме отдельно разрешённых целых и рациональных случаев |
| `arcsin(u)`, `arccos(u)` | `−1≤u≤1` |
| `tan(u)` | аргумент не совпадает с полюсами тангенса |
| `acosh(u)` | `u≥1` |
| `atanh(u)` | `−1<u<1` |
| `exp(u)`, степени и композиции | результат не должен переполняться или становиться нечисловым |

Если композиция имеет разрыв между наблюдениями, проверки только в узлах недостаточно. Для параметризованных знаменателей, логарифмов и тригонометрических полюсов требуется аналитическое доказательство по границам аргумента либо консервативная проверка интервала. Нельзя маскировать разрыв возвратом константы или незаметным `clip`.

Недопустимый кандидат получает статус `invalid` с причиной. Он не участвует в отборе.

## 6. Канонизация и упрощение

Перед оценкой сложности выполняются безопасные преобразования:

- объединение численных констант;
- удаление `+0`, `·1`, степени `1`;
- замена выражения с нулевым множителем на `0`, если оба аргумента допустимы;
- сортировка коммутативных аргументов по стабильному структурному ключу;
- объединение структурно одинаковых кандидатов;
- сокращение эквивалентных параметризованных поддеревьев.

Нельзя выполнять тождества, меняющие область определения, без отдельной проверки. Например, сокращение `x/x→1` недопустимо при `x=0`.

## 7. Сложность

Сохраняются одновременно:

- число узлов дерева;
- глубина дерева;
- число свободных численных параметров;
- число нелинейных параметров;
- взвешенная сложность для отбора.

Веса узлов и параметров фиксируются конфигурацией до запуска. Изменять их после просмотра контрольных результатов запрещено.

## 8. Сериализация

Для каждой формулы сохраняются:

1. дерево в машинно-читаемом виде;
2. читаемая формула;
3. список переменных и их происхождение;
4. значения и границы параметров;
5. сложность;
6. структурный хеш для кеширования;
7. результат проверки области определения.
