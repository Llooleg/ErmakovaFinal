# Архитектура системы символьной регрессии

## 1. Назначение

Документ определяет архитектуру программы, реализующей требования `plan.md`. Программа должна автоматически находить непрерывную аппроксимирующую функцию многих переменных, изменяя как структуру выражения, так и его численные параметры.

Связанные спецификации:

- `expression-language.md` — представление формул и каталог функций;
- `search.md` — генетическое программирование, оптимизация параметров и выбор решения;
- `evaluation.md` — метрики, коридор 5 %, контрольная проверка и журналирование.

## 2. Основные определения

- **Выражение** — дерево, состоящее из переменных, констант, арифметических операций и элементарных функций.
- **Структура** — дерево без фиксированных численных значений свободных параметров.
- **Кандидат** — структура с конкретными значениями параметров.
- **Обучение** — построение структур и оценка их параметров на обучающем участке.
- **Валидация** — последовательная временная проверка внутри обучающего участка для сравнения кандидатов.
- **Контроль** — финальная проверка замороженного решения на данных, не участвовавших в поиске.
- **Сложность** — измеримый размер дерева и количество свободных параметров.

## 3. Границы решения

Система выполняет аппроксимацию предоставленного CSV. Она не собирает новые данные, не обращается к живым целям и не требует старые ГА-коэффициенты или деревья решений.

Система не должна незаметно выбирать смысл независимых переменных или критерия 5 %. Эти решения являются обязательными полями конфигурации эксперимента.

## 4. Логические компоненты

1. **DataLoader** — читает CSV, проверяет схему, сортирует наблюдения по времени и отклоняет дубли временных меток.
2. **FeatureProvider** — создаёт независимые переменные согласно конфигурации: время, прошлые значения или другие разрешённые производные исходных колонок.
3. **ExpressionTree** — хранит дерево формулы, поддерживает копирование, сериализацию, канонизацию и расчёт сложности.
4. **PrimitiveCatalog** — содержит все поддерживаемые операции, их сигнатуры, области определения и правила непрерывности.
5. **SafeEvaluator** — вычисляет выражение без исполнения произвольного кода и отклоняет значения вне области определения.
6. **ParameterOptimizer** — оптимизирует коэффициенты, степени, периоды и сдвиги.
7. **GPEngine** — создаёт популяцию и выполняет скрещивание, мутацию, отбор и сокращение деревьев.
8. **ParetoSelector** — отделяет кандидатов, удовлетворяющих коридору, и строит фронт «ошибка — сложность».
9. **MetricsEvaluator** — рассчитывает обязательные метрики и покрытие коридора.
10. **ExperimentReporter** — сохраняет конфигурацию, результаты, формулы, графики и запись в `REPORT.md`.

Логические компоненты можно объединять в файлы, но их ответственность не должна смешиваться: метрики не изменяют поиск, а контрольная выборка недоступна `GPEngine` и `ParetoSelector`.

## 5. Конвейер выполнения

1. Загрузить конфигурацию и CSV.
2. Проверить данные и построить причинно допустимые переменные.
3. Зафиксировать обучающий, внутренний валидационный и контрольный участки.
4. Передать в поиск только обучение и внутреннюю валидацию.
5. Создать начальную популяцию простых выражений.
6. Оценить допустимость и оптимизировать параметры кандидатов.
7. Выполнить поколения ГП в пределах заданного бюджета.
8. Построить фронт Парето по валидационным результатам.
9. Выбрать и заморозить итоговую формулу по заранее заданному правилу.
10. Один раз рассчитать контрольные метрики.
11. Сохранить артефакты и дополнить `REPORT.md`.

## 6. Обязательная конфигурация

Каждый эксперимент должен однозначно сохранять:

| Группа | Обязательные сведения |
|---|---|
| Данные | путь к CSV, названия колонок, единица времени, правила пропусков |
| Переменные | имена `x₁…xₘ`, способ вычисления каждой переменной, доступная история |
| Разбиение | границы обучения, валидации и контроля, режим прогнозирования |
| Каталог | разрешённые функции и операции |
| Параметры | диапазоны коэффициентов, степеней, периодов и сдвигов |
| Дерево | максимальная глубина, число узлов и свободных параметров |
| ГП | размер популяции, поколения, вероятности операторов, seed |
| Оптимизация | метод, границы, критерий остановки, лимит вычислений |
| Коридор | знаменатель относительной ошибки и требуемое покрытие |
| Выбор | правило выбора точки излома и критерий предпочтения простых формул |

Значения, отсутствующие в исходном задании, не получают скрытых значений по умолчанию. Программа обязана сообщить о незаполненной обязательной конфигурации до начала поиска.

## 7. Выходные артефакты

Каждый завершённый эксперимент сохраняет:

- неизменённую копию конфигурации;
- seed и версии зависимостей;
- итоговую формулу и список параметров;
- Pareto-фронт с метриками и сложностью;
- CSV с фактом, прогнозом, ошибками и относительными ошибками;
- JSON или YAML с машинно-читаемыми метриками;
- графики факта, аппроксимации, ошибок и Pareto-фронта;
- запись в `REPORT.md`.

## 8. Ограничения качества

- Никакого `eval` для пользовательских или сгенерированных строк формул.
- Никакого доступа к будущим наблюдениям при построении признаков.
- Никакого выбора модели по контрольным метрикам.
- Никакого неограниченного роста дерева.
- Никаких заявлений о выполнении ТЗ без запуска программы и тестов.
